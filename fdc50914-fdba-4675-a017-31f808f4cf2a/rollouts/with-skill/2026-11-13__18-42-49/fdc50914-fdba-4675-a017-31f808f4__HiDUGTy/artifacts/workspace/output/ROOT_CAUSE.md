# RegExp repair evidence and limits

The authority used here is `/workspace/spec/ecma262-2025.html`, particularly 22.2.1 (grammar and early errors), 22.2.1.8 (MayContainStrings), and 22.2.2 (pattern semantics). This report describes identified causes; it is not a proof that these are every possible defect in the engine. The request for complete grammar conformance and for all existing tests to pass has a concrete conflict described below.

## 1. Causes and governing rules

* **Loop state escaped its invocation.** EnterLoop overwrote `iters` without an undo record. Backtracking into an earlier invocation of the same nested quantifier could therefore use another invocation's count. Assertion execution also retained loop state while discarding its undo stack. RepeatMatcher (22.2.2.3.1) passes min/max and the preceding MatchState by value to continuations: another invocation cannot modify those values. Its step 2.b rejects empty optional iterations; corrupt counts invalidate that decision too. The repair saves loop state at entry and isolates assertion loop state.
* **Capture completion was not independently undoable.** EndCaptureGroup wrote an endpoint without an undo record. Backtracking within the group could expose the endpoint of an abandoned completed match to an internal reference. CompileSubpattern's capturing-group continuation and BackreferenceMatcher require the captures belonging to the current path. Completion now saves its previous state, just as capture entry already did.
* **Duplicate-name validation confused unrelated disjunctions.** Paths used parenthesis depth as disjunction identity. Distinct sibling disjunctions can have different alternative numbers without being mutually exclusive. The GroupSpecifier early error in 22.2.1 requires a common Disjunction with the names in distinct Alternatives. Paths now carry unique disjunction identities and compare only common identities.
* **Duplicate-name references used alternation.** An unmatched reference succeeds empty, so an alternative referring to an unmatched duplicate could bypass the participating capture. GroupSpecifiersThatMatch (22.2.1.9) and BackreferenceMatcher select the participating capture. References now concatenate the candidate references: with valid duplicate names, at most one participates and the others consume nothing. The API's named_group also used only the first name occurrence; it now finds the participating occurrence, consistently with named_groups.
* **The v flag did not enable Unicode semantics elsewhere.** Unicode traversal, escape validation, canonicalization, and word boundaries tested `unicode` alone. HasEitherUnicodeFlag and Canonicalize (22.2.2.7.3) apply for either u or v. Parsing now rejects simultaneous u/v and normalizes v to Unicode mode internally.
* **Set operations preceded case equivalence.** Expanding only the final set loses intersections such as `[a&&A]` and retains subtractions such as `[a--A]` under iv. CompileToCharSet (22.2.2.9), MaybeSimpleCaseFolding and the ClassIntersection/ClassSubtraction productions require operations on canonicalized operands. Operands now use case-closed character sets and canonicalized strings before algebra. One-character q strings are normalized into character sets so the two representations intersect identically.
* **Complements used the wrong folding order.** Atom property escapes used u's complement-before-closure rule in v too. Conversely, W inside classes was complemented before recognizing Unicode case equivalents of word characters. CompileToCharSet's CharacterClassEscape productions distinguish these operations. v property complements and Unicode W now complement case-closed positive sets; u property escape behavior is retained.
* **String sets discarded empty alternatives.** The q parser dropped every empty ClassString. The grammar admits empty ClassString, and its compiled value contains the empty string. Empty alternatives are now retained, tried after longer strings and one-character members. They also participate in intersection and subtraction.
* **Negation lacked the required static string check.** Checking individual string-property operands could reject a legal intersection, while q strings escaped checking entirely. MayContainStrings is syntax directed: union uses OR, intersection AND, subtraction the left operand; empty and multi-character ClassStrings return true. Metadata now follows these rules, and the CharacterClass/NestedClass negation early errors check the completed expression, even if subtraction removes all actual strings.
* **v grammar character handling was inaccurate.** A lone ampersand after the first operand lost that first operand. The reserved-double-punctuator check rejected two different punctuation characters, although the grammar enumerates identical pairs. Brackets were accepted as bare ClassSetCharacters in string contents. Escaped b produced the letter b rather than U+0008. These are repaired according to ClassSetCharacter, ClassSetSyntaxCharacter, ClassSetReservedDoublePunctuator and CharacterEscape.
* **String-set lookbehind used forward sequence order.** Ordinary concatenations were reversed for backward matching, but StringSet was opaque to that walk and emitted its characters forward. CompileSubpattern with direction backward requires matching each string from its end. Emission now reverses the code-point instruction order in lookbehind, preserving each UTF-8 literal's byte encoding.
* **Unicode escape parsing admitted non-HexDigits and lost input.** Rust radix parsing admits a leading plus; the grammar's HexDigits does not. A high-surrogate escape followed by an escape that was not a low surrogate could consume the second escape's prefix during the failed pair attempt. HexDigits are now explicitly checked and the entire second escape is restored on failed pairing.
* **Escaped group-name delimiters were treated as syntax.** The name parser tested for `>` after decoding an escape, accepting an escaped delimiter as the end of GroupName instead of rejecting it as an invalid RegExpIdentifierPart. It now recognizes the literal delimiter before escape decoding.
* **Budget exhaustion could turn assertion failure into success.** A negative assertion could negate an exhausted attempt, and searching could continue after exhaustion. Exhaustion now propagates through assertion/search success paths. This is an API correctness issue; ECMA-262 itself has no budget outcome.

## 2. Why the existing tests passed

The original suite passed after the initial fixes, so those checks did not distinguish the faulty implementations. Existing tests do not constitute an exhaustive composition of nested quantifiers, backtracking within completed groups, sibling disjunctions sharing names, or v set algebra with case equivalence, emptiness and negation. The source exposes these missing distinctions directly. No claim is made about the intent of the test authors.

Some existing tests positively require nonstandard behavior: `run_regexp_unicode_escape_tc` requires `\u{0}` with an empty flag string to match NUL; `test_escapes_folding_tc` requires `\u{41}` without Unicode flags to match A. The grammar does not permit a braced Unicode code-point escape in that mode. Changing this caused four existing test functions to fail. That restriction was reverted to meet the explicit existing-test requirement. Thus full grammar equivalence has **not** been achieved.

## 3. Other affected patterns

The state causes apply to repeated invocations of nested counted, greedy or lazy quantifiers, in either matching direction, and groups with backtracking alternatives and internal references. Name causes apply to any sibling disjunctions with repeated names and to references before or after duplicate groups. Set causes extend to nested sets, escaped properties, q strings of any length, case equivalents outside ASCII, chained intersections/subtractions and empty strings. The v mode cause extends to astral inputs, invalid identity escapes and numeric references. Escape rollback affects any high-surrogate escape followed by a non-low-surrogate escape.

## 4. Engine changes

Changes are confined to `src/api.rs`, `src/classicalbacktrack.rs`, `src/parse.rs` and `src/emit.rs`. No API signatures or dependencies change. The parser normalizes flags and set operands, tracks static string information and disjunction identity, validates characters and lowers references correctly. The VM makes state mutations reversible and propagates exhaustion. Emission handles backward strings. Focused tests live under src in `conformance_repairs`.

## 5. Behaviors retained

UTF-8 results remain byte ranges; UTF-16 and UCS2 results remain code-unit ranges. Numeric references to unmatched groups still succeed empty. Greedy/lazy priority, ordinary alternative priority, and positive assertion atomicity retain their existing implementation. u property complements retain complement-before-case-closure. Budget limits remain limits rather than being increased. The crate's legacy acceptance of braced Unicode escapes without Unicode flags is retained, with the conformance limitation above.

## 6. Determining expected results

The focused checks derive expectations from the local grammar and algorithms, without using another regex engine as an oracle. For `[a&&A]/iv`, both operands denote the same case class, so a must match; their subtraction is empty. An empty q ClassString supplies an empty match, but a longer matching member is attempted first. The named-reference checks select b's capture and therefore require a second b. Negated q expressions use MayContainStrings, rather than inspection of the resulting set. Lookbehind `(?<=[\q{ab|c}])d` succeeds at d in abd by reading b then a. The astral UTF-8 witness spans bytes 1..5; the UTF-16 duplicate emoji reference spans units 1..5 with capture 1..3. Tests assert the respective ranges and participating named capture.

## 7. Detection checks

`conformance_repairs::spec_witnesses` checks budgeted matches/nonmatches, internal references after group backtracking, duplicate references/captures, iv intersection/subtraction, q emptiness and priority, backspace, punctuation, complements, nested empty quantifiers, lookbehind strings, escape rollback and astral byte ranges. `spec_early_errors` checks sibling-disjunction duplicate names, negative empty/multichar q strings, operator mixing, reserved pairs, identity escapes, invalid numeric references non-HexDigits and escaped group-name delimiters. `code_unit_ranges` checks UTF-16 and UCS2 ranges. A stronger state check would enumerate small nested quantified ASTs and compare their full captures against an independent continuation interpreter of RepeatMatcher, in both directions. That exhaustive differential check was not performed; `assertion_exhaustion_is_not_a_match` additionally checks exhaustion inside a negative assertion.

## 8. Interactions

Correct name validation is a precondition for concatenating duplicate references: it guarantees at most one candidate can participate. Reversible capture state is also needed to maintain that invariant during backtracking. v mode normalization enables correct folding and traversal, but does not by itself fix set-operation order. Empty q members interact with quantifier progress rejection and longest-first class-string matching. Static string metadata must survive operations even when the resulting string set is empty. Assertions discard local backtrack stacks, so loop restoration must be independent of that discarded stack.

## 9. Not established

The evidence does not establish exhaustive ECMAScript 2025 conformance, or that every terminating specification match fits a one-million-step classical-backtracking budget. In particular, non-Unicode braced escapes remain a known incompatibility forced by existing tests; arbitrary huge counted repetitions and all Unicode property data were not independently validated.

## 10. Scope of causal claims

The claims above follow from inspected mutation/parse paths, the cited specification rules and the focused checks. Passing the suite is regression evidence, not proof of universal correctness. No claim is made that an untested pattern is correct merely because it resembles a witness, or that these identified causes exhaust all possible failures.

## Final validation

Both `cargo test --offline` and `cargo test --offline --features utf16` completed successfully, including the new focused checks and doctests (one existing ignored doctest). Commands were run against `/workspace/regress/Cargo.toml`. No network was used. `cargo fmt` is unavailable in this environment; it did not modify files. No tests outside src were edited.
